## 三、E1: arxiv MCP 工具验证

### 实验设计

| 项目 | 内容 |
|------|------|
| 目的 | 验证 arxiv MCP 是否提升论文检索的相关性与可验证性 |
| 条件 | `arxiv_on`：启用 arxiv MCP 检索 [D][E][F]；`arxiv_off`：仅用 Brave Search 检索 |
| 规模 | 5 cases × 2 conditions × 3 runs |
| 工具栈 | pdf + brave search + citation-standard (+ arxiv\_mcp if on) |

### 结果

| 指标 | arxiv\_off | arxiv\_on | 结论 |
|------|:---:|:---:|------|
| 贴合分数（LLM 评分） | 略高 | 略低 | 无显著差异，on 不提升 relevance |
| C5 贴合分数 | 显著低于 C1–C4 | 显著低于 C1–C4 | C5 是 hard case，不论开关 |
| 检索真实性 | 较低 | 较高 | on 条件更容易找到真实存在的论文 |

### 关键发现

- arxiv MCP 提升的是**检索真实性与可验证性**，不是**主题贴合度**
- C5 不论开关均表现最差——LLM 对 "AI coding agents 替代初级工程师" 的判定倾向于低估论文相关性
- 该实验证明 arxiv MCP 值得在后续实验中固定开启

## 四、E2: Refchecker Repair 效果

### 实验设计

| 项目 | 内容 |
|------|------|
| 目的 | 验证 mcp-refchecker 是否能帮助 Agent 发现并修复引用错误 |
| 条件 | `repair_no`：ORIGINAL\_REPORT；`repair_yes`：refchecker 核查后 REPAIRED\_REPORT |
| 规模 | 5 cases × 3 runs |
| 工具栈 | pdf + brave search + arxiv MCP + citation-standard + refchecker |
| 评测方式 | citation\_check 流水线：人工定义错误分类体系 + few-shot prompt → LLM (DeepSeek) 逐 claim 分类 |

### 错误分类体系

| 错误类型 | 定义 |
|------|------|
| **Overclaim** | 结论强于原文证据（扩大适用范围、加强断言强度、做论文没做的泛化） |
| **Mis-citation** | 被引论文沾边但接不上：讨论的是另一个对象/任务/指标，或引用位置错误 |
| **Unsupported Claim** | 在被引论文证据中完全找不到支撑该 claim 的依据 |
| **Contradiction** | claim 与论文内容相反或冲突 |

### 结果：按 Case × Repair 汇总（均值 ± std，3 runs）

| Case | Original (repair=no) | Repaired (repair=yes) | 变化 |
|------|:---:|:---:|:---:|
| C1 | 2.7 ± 1.5 | 2.0 ± 1.0 | ↓ 0.7 |
| C2 | 2.7 ± 1.2 | 3.0 ± 1.0 | ↑ 0.3 |
| C3 | 4.3 ± 2.3 | 4.3 ± 2.3 | = |
| C4 | 1.7 ± 1.2 | 2.0 ± 1.0 | ↑ 0.3 |
| C5 | 3.0 ± 1.4 | 3.0 ± 2.8 | = |
| **Total** | **40** | **40** | **0** |

### 结果：按错误类型汇总

| 错误类型 | Original | Repaired | 变化 |
|------|:---:|:---:|:---:|
| Overclaim | 14 | 14 | = |
| Mis-citation | 8 | 9 | ↑ 1 |
| Unsupported Claim | 17 | 16 | ↓ 1 |
| Contradiction | 1 | 1 | = |

### 关键发现

1. **Repair 没有减少错误总量（40 → 40）**，只有 C1 有轻微改善
2. **错误类型漂移而非消除**：20 个配对 claim 中 7 个错误类型改变（如 Overclaim → Mis-citation），总量不变
3. **C3（生化）Unsupported Claim 占 85%**，repair 完全无效——refchecker 验证元数据，不验证语义支撑
4. **领域越专业，repair 越无效**：C1（主流 CS）> C4 > C2 > C5 > C3（生化）

## 五、E3: Memory MVP

### 实验设计

| 项目 | 内容 |
|------|------|
| 目的 | 验证 Agent 是否能从之前的 refchecker/repair 经验中学习 |
| 条件 | M0 (no memory)：无跨 case 记忆；M1 (memory on)：repair log 写入 memory，下个 case 检索注入 |
| 规模 | 5 cases × 2 passes (P1 → P2) |
| Memory 来源 | 仅注入 REFCHECKER\_REPAIR\_LOG 的规范化摘要，不写入完整报告 |
| 工具栈 | pdf + brave search + arxiv MCP + citation-standard + refchecker (+ memory if M1) |

### 结果：M1 逐 Run 错误计数

| Case | Run1-M1 | Run2-M1 |
|------|:---:|:---:|
| C1 | 1 | 1 |
| C2 | 0 | 1 |
| C3 | 4 | 3 |
| C4 | 2 | 1 |
| C5 | 0 | 3 |
| **Sum** | **7** | **9** |

### 结果：M1 分错误类型

| 错误类型 | Run1-M1 | Run2-M1 |
|------|:---:|:---:|
| Overclaim | C1=1, C3=1 | C1=1, C2=1, C4=1, C5=2 |
| Mis-citation | C4=1 | C5=1 |
| Unsupported Claim | C3=3, C4=1 | C3=3 |
| Contradiction | 0 | 0 |

### 结果：M0 vs M1 对比

| | M0 | M1 | 变化 |
|------|:---:|:---:|:---:|
| Run1 总量 | 11 | 7 | ↓ 36% |
| Run2 总量 | 11 | 9 | ↓ 18% |
| **全量** | **22** | **16** | **↓ 27%** |

### 关键发现

1. **Memory 减少错误总量 27%**，效果优于 refchecker repair（repair 总量不变）
2. **C1 + C2 改善最明显**：主流 CS 话题从 memory 获益最大
3. **C3 完全无效**：Unsupported Claim 100% 集中在 C3，memory 无法弥补生化领域知识鸿沟
4. **Contradiction 清零**：memory 条件下无此类型错误
5. **C5 两 run 差异大**：Run1=0, Run2=3，memory 效果不稳定

## 七、归因总结

| # | Insight | 支撑实验 |
|---|---------|---------|
| 1 | arxiv MCP 提升检索可验证性，不提升主题贴合度 | E1 |
| 2 | refchecker 做 Citation verification，不代替 Claim verification | E2 |
| 3 | repair 是错误类型漂移，不是错误消除 | E2 |
| 4 | 领域专业度越高，工具辅助越无效 | E2 + E3 |
| 5 | Memory 比 refchecker repair 更有效 | E3 |
| 6 | Memory 消除 Contradiction，但不解决 Unsupported Claim | E3 |
| 7 | C3（生化）是三个实验的共识 hard case | E1 + E2 + E3 |
