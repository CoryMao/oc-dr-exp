# arxiv-MCP机制探索

## 遇到的问题

我们发现，当我们以查找论文与选题的贴合程度去进行分数量化时，arxiv-MCP的开关与其贴合度并无显著相关性。相反，大部分开启的情况贴合程度的得分反而略低于off。
同时最为重要的是：在case5，无论开关均表现出了较其他case贴合程度的显著下降！！！

## 原因分析

1. 第一层：“为什么这个结果本身是合理的”：

- arxiv-mcp 和 refchecker-mcp 的主要作用，不是直接优化“和题目有多贴”，而是优化“能不能找到真实论文、拿到更可靠的论文元数据、减少幻觉引用”。前者更偏真实 arXiv 检索与读论文，后者更偏引用核验与元数据校对，所以它们最多是间接影响贴合度，不是专门的 relevance optimizer。
- 结合我们的实验，这意味着：on 条件更容易找到真实存在、可验证的论文，但这些论文未必更靠近题目中心，这个现象本身是正常的。对应说明可以落在“工具增强提升的是检索真实性与可验证性，而非主题贴合度上界；每次 run 的输出仍然具有检索排序与候选采样的不确定性”上。

2. 第二层： C5 的机制。

- 从最新这版明细看，b1_detailed_results.csv 里 C5 的 arxiv_on 明显更容易选到论文典型类别有：
需求工程：Using LLMs in Software Requirements Specifications...
安全风险：Is Vibe Coding Safe?...
开发者感知/社会讨论：Will Agents Replace Us?...
工作流影响：Code with Me or for Me?...
质量与复杂度影响：Speed at the Cost of Quality...
这些论文大多只拿 1-2 分，因为大语言模型判断它们更多在谈软件开发中的 LLM 影响，而不是AI coding agents 是否具备替代初级软件工程师的核心能力边界。并将其认为是低度相关。
- 这里一定程度上反映了大语言模型在界定相似或贴合度方面的局限。
