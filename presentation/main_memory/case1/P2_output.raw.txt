## 第一部分：总体评估

围绕"Tool-augmented LLM agents 是否优于纯 LLM prompting 解决复杂编程任务"这一课题，六篇论文 [A]–[F] 提供了多角度的证据。总体来看，证据强烈支持 tool-augmented 的 agent 系统在复杂编程任务上显著优于纯 prompting / RAG 基线。SWE-agent [F] 在 SWE-bench Lite 上的解决率是 RAG 基线的约 6.7 倍（18.00% vs 2.67%）；Trae Agent [B] 在 SWE-bench Verified 上达到 75.20% Pass@1 的领先成绩。然而，Agentless [E] 提出了重要反例：一个不含自主决策的简化管线在 SWE-bench Lite 上达到 32.00%，超过了所有当时的开源 agent 方法，表明并非所有场景都需要复杂的自主 agent。

当前研究的共识是 agent 框架能显著提升 LLM 在复杂软件工程任务上的表现，但分歧在于：agent 架构的最佳复杂度边界在哪里？[A] 展示 agent 可通过自编辑代码实现自我改进（SWE-Bench Verified 从 17% 提升至 53%），但这种改进在推理密集型任务（AIME/GPQA）上收效甚微，提示了 agent 框架增益与底层模型能力之间的重要交互。[D] 的 ADAS 框架进一步展示了自动搜索 agent 设计的潜力。主要局限包括：benchmark 数据污染风险、评估成本极高（[A] 单次 15 轮实验耗资约 $7,000），以及 agent 改进的路径依赖问题。

## 第二部分：逐条结论

- 结论 1：配备工具的 LLM agent 在复杂软件工程任务上的表现远优于纯 prompting / RAG 方法，在 SWE-bench Lite 上 SWE-agent（18.00%）比 RAG（2.67%）提升约 6.7 倍。
  出处：[F] §5::T1

- 结论 2：基于 agent 的集成推理（ensemble reasoning）配合分层剪枝和选择器 agent，能显著超越单 patch 生成和基于 prompting 的集成方法，Trae Agent 相比基线平均提升 10.22% Pass@1。
  出处：[B] §1::T5 / [B] §5

- 结论 3：LLM agent 可通过自主编辑自身代码库实现性能的持续改进，而无需修改模型权重，在 SWE-Bench Verified 随机子集上从 17% 提升至 53%。
  出处：[A] §4::T1 / [A] §5

- 结论 4：LLM agent 能够从科学论文及其代码仓库中自主生成可执行的 LLM 兼容工具，ToolMaker 在 TM-BENCH 15 项任务中正确实现了 80%。
  出处：[C] §4

- 结论 5：不含自主决策的简化"agentless"管线在 SWE-bench Lite 上达到 32.00% 解决率，超过了当时所有开源 agent 方法，以极低成本（$0.70/issue）重设了基线。
  出处：[E] §1 / [E] §3

- 结论 6：Agent-Computer Interface（ACI）设计对 agent 性能有显著影响——SWE-agent 的自定义 ACI 相比 Shell-only 基线实现 64% 的相对提升。
  出处：[F] §5.1::T3

- 结论 7：自改进 agent 在推理密集型任务（如 AIME 2024 和 GPQA Diamond）上的增益远低于编码任务，当底层推理模型已表现良好时，额外的 agent 框架可能反而干扰推理链。
  出处：[A] §4.1 / [A] §4.1::F4

- 结论 8：自动搜索 agent 设计空间能够发现超越人工设计的 agent 架构，Meta Agent Search 在 ARC、DROP 等多个领域的实验中持续优于手工设计的基线。
  出处：[D] §4.1 / [D] §4.2
